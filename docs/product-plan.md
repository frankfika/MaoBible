# MaoBible 产品方案

> 工作定位：一个轻松、克制、可信的多语言毛泽东著作阅读与思想研习产品。

## 1. 产品定义

MaoBible 不做传统电子书，也不做厚重的知识门户。

它提供三种核心体验：

1. **读原文**：舒服地阅读、搜索、收藏和做笔记。
2. **懂方法**：用简短导读、历史语境和思想主题理解文章。
3. **跨语言**：在中文、英文等版本之间快速切换和对照。

产品原则：

- 原文优先，解释克制
- 每个观点都有出处
- 先让人愿意读，再帮助人读懂
- 不要求登录即可使用核心功能
- 不堆功能，保持安静和轻盈

## 2. 目标用户

第一阶段聚焦三类用户：

- 想系统读《毛泽东选集》，但不知道从哪里开始的人
- 对战略、组织、实践、矛盾分析等方法感兴趣的人
- 海外中文学习者、研究者，以及需要外文版本的读者

## 3. 产品结构

移动端保留四个主入口：

### Today

- 每日一段
- 3 分钟导读
- 继续上次阅读
- 一个简短思考问题

### Library

- 按卷、时间和文章浏览
- 全文搜索
- 收藏、划线、笔记
- 阅读进度与离线保存

### Explore

- 思想主题：实践、矛盾、调查、战略、组织、学习
- 历史时间线
- 文章之间的关联
- 精选阅读路径

### Me

- 笔记与收藏
- 阅读历史
- 语言与显示设置
- 离线内容

第一版不单独设置 AI Tab。未来 AI 作为阅读页里的辅助能力出现，避免产品变成普通聊天工具。

## 4. 阅读体验

阅读页是产品核心，结构保持简单：

1. 标题、时间、预计阅读时长
2. 一张可收起的导读卡
3. 原文正文
4. 段落操作：划线、笔记、解释、对照
5. 文末的思想要点与关联文章

关键交互：

- 单击段落打开轻量工具条
- 左右滑动切换上一篇、下一篇
- 顶部只保留返回、语言、目录三个按钮
- 阅读时自动隐藏界面控件
- 中外文可选择“单语切换”或“段落对照”
- 每个段落使用稳定 ID，保证不同语言精确对齐

## 5. 多语言方案

多语言不是后期翻译插件，而是底层内容能力。

### 首发语言

- 简体中文 `zh-CN`
- English `en`

后续可加入：

- 繁体中文 `zh-TW`
- Español `es`
- Français `fr`
- 日本語 `ja`
- Русский `ru`

### 两种语言独立控制

- **界面语言**：按钮、导航、设置等 UI 文案
- **内容语言**：原文、导读、主题解释

例如用户可以使用英文界面阅读中文原文，也可以使用中文界面阅读中英对照。

### 内容数据结构

```text
Work
└── Article
    ├── metadata
    ├── zh-CN
    │   └── paragraph-001...
    ├── en
    │   └── paragraph-001...
    └── annotations
```

每个翻译版本记录：

- 语言
- 译者或来源
- 版本信息
- 审校状态
- 授权状态
- 更新时间

术语建立统一词表，确保“实践”“矛盾”“群众路线”等核心概念在不同文章中的译法稳定。机器翻译只能用于草稿，公开内容必须经过人工审校。

## 6. 视觉方向

关键词：

> quiet、warm、editorial、chill、timeless

不使用大面积正红、金色、复杂纹样或宣传画式构图。整体像一本排版很好的独立杂志和现代阅读器。

### 色彩

- Paper：`#F4F1EA`
- Ink：`#22221F`
- Secondary：`#77766F`
- Moss：`#6F7868`
- Cinnabar：`#A44A42`，只用于少量重点
- Dark Paper：`#191918`

### 字体

- 中文标题：现代宋体
- 中文正文：屏幕优化宋体或黑体，由用户选择
- 英文正文：Source Serif 4
- UI：Inter / Noto Sans

### 界面规则

- 大留白，低密度导航
- 卡片弱边框、无重阴影
- 圆角控制在 12–18px
- 正文默认 17–18px，行高约 1.8
- 动效 180–260ms，只做淡入、轻微位移和按压反馈
- 完整支持深色模式与减少动态效果
- 手机优先，同时适配平板和桌面浏览器

## 7. 内容体系

每篇重点文章最多提供四类辅助内容：

- **Before Reading**：写作背景和要解决的问题
- **Key Ideas**：3–5 个核心观点
- **Structure**：文章论证结构
- **Connections**：相关主题和文章

解释内容必须区分：

- 原文
- 编辑导读
- 译文
- 后期 AI 辅助内容

所有引文可以回到具体文章和段落，避免脱离语境的“金句化”。

## 8. MVP 范围

第一版只做完整的核心体验：

- 20 篇代表性文章
- 中文、英文双语
- Today、Library、Explore、Me
- 舒适阅读器
- 单语切换与中英对照
- 搜索、收藏、划线、笔记
- 6 个思想主题
- 3 条精选阅读路径
- PWA 安装与基础离线
- 深色模式

第一版暂不做：

- 社区与评论
- 复杂账号体系
- 用户公开内容
- 音视频课程
- 付费系统
- 独立 AI 聊天页面

## 9. 技术路线

### H5 / PWA

- React + TypeScript + Vite
- Tailwind CSS
- i18next 管理界面多语言
- MDX + 结构化 JSON 管理内容
- IndexedDB 保存阅读进度、笔记和离线内容
- Service Worker 提供 PWA 和离线能力

第一阶段内容跟随版本发布，不依赖后端即可工作。账号同步、内容管理和 AI 能力成熟后再增加 API 与数据库。

### App

H5 稳定后使用 Capacitor 封装：

- iOS
- Android

App 版本增加离线书库、原生分享、通知和本地数据保护等能力。核心界面与内容代码继续复用，避免维护两套产品。

## 10. 开发阶段

### Phase 1：产品原型

- 确定品牌名和视觉系统
- 完成 Today、Library、Reader 三个关键页面
- 建立双语段落数据格式
- 录入 3 篇示范文章

目标：验证产品气质和双语阅读体验。

### Phase 2：H5 MVP

- 完成四个主入口
- 扩充到 20 篇文章
- 加入搜索、笔记、主题和阅读路径
- 完成 PWA 与离线功能

目标：发布可长期使用的公开测试版。

### Phase 3：内容与智能能力

- 增加更多语言和文章
- 建立可靠的引用检索
- 加入段落解释、概念关联和有出处的 AI 问答

### Phase 4：App

- Capacitor 封装
- 增加原生通知、分享和离线包
- 完成 iOS/Android 真机适配与上架

## 11. 内容与版权

上线前需要为原文、译文、照片、封面和导读分别维护来源及授权状态。

- 不直接复制来源不明的电子书
- 不默认不同语言译本可以自由使用
- 图片和历史照片单独核查
- 具体版本、译者和出处在产品内透明展示
- AI 生成内容必须标识，并由编辑审校

## 12. 成功标准

第一版重点观察：

- 用户是否会完成一篇文章
- 是否会在一周内再次打开
- 双语对照是否真正被使用
- 哪些思想主题能带动继续阅读
- 收藏、划线和笔记是否自然发生

北极星指标：

> 每周完成至少一次有效阅读的用户数。

有效阅读可以定义为：阅读一篇文章超过一定比例，或完成划线、笔记、主题跳转中的任意一项。

## 13. 最终方向

MaoBible 的体验应该像：

> 随手打开很轻松，真正读进去又足够深。

先用一个完成度高、双语、安静的 H5 阅读产品建立基础，再逐步加入思想地图、可靠的 AI 研习能力和原生 App。视觉不抢内容，功能不打扰阅读，所有解释始终可以回到原文。
